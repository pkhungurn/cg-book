16   Programming with matrices

In the last chapter, we learned about 2D transformations and why they matter in computer graphics. HOwever, we only learned the theory and yet do not know how to use transformations and matrices in our programs. This chapter will fill in the missing practical aspect.

Because matrices are so frequenly used in computer graphics applications, there are support for them at multiple levels in the WebGL programming tool chain. First, GLSL has native data types for matrices up to the size of $4 \times 4$. It also have built-in functions for common matrix operations such as transposition, computing invereses, and computing determinants. Second, there are open-source Javascript libraries for "3D math," which generally have support for up to 4D vectors (which can represent 3D points) and matrices that can act on these vectors. For this book, we will use a well-known library called glMatrix.

16.1   Matrices in GLSL

The GLSL programming language comes packed with language-level features for maniputing small matrices up to size $4 \times 4$. This means that we can easily represent and manipulate 3D affine transformations with the language.

16.1.1   Data types

GLSL has the following built-in data types for matrices:

mat2x2, mat2x3, mat2x4,
mat3x2, mat3x3, mat4x4,
mat4x2, mat4x3, and mat4x4.

Obviously, we can read the size of the matrices each data type represents from its name. However, unlike the convention we used in the last chapter, the first number is the number of column, and the second number is the number of rows. So, mat3x4 represents matrices with 3 columns and 4 rows, which is written as $4 \times 3$ according Chapter 15's convention. The author admits that this can be confusing.

Nevertheless, we will use square matrices almost all the times, so the types that matter to us are mat2x2, mat3x3, and mat4x4. We can refer to these types by their shorter names:

mat2, mat3, and mat4.

Matrix entries are single-precision floating point numbers; i.e., the float data type in GLSL. While other versions of GLSL have support for matrices whose entries are double-precision floating point nubmers, the GLSL we can use with WebGL does not have this feature.
